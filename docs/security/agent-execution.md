# Agent execution security

Agent prompts, repository content, tool output, and model output are untrusted. Run adapters only inside an AgentOS-managed isolated runtime with a run-scoped workspace, explicit resource and network policy, no host credentials, and no Docker socket. A separate Git worktree protects developer edits from direct mutation but is not a security boundary. Never silently execute on the host if a sandbox is missing.

OpenCode permissions are an additional application-level control, not an OS sandbox. `ExecutionCoordinator` currently permits only `read_only`; permission requests are persisted as rejected before sending the rejection response, and secret-like strings are redacted from approval descriptions/resources. This is a deny-only enforcement path. It does not implement trusted user identity, approval expiry/revocation, capability-bound authorization or replay consumption. The Docker runtime implementation mounts one detached worktree read-only, uses `--network=none`, loopback-only port publishing, non-root UID, `--read-only`, dropped capabilities, no-new-privileges, pid/memory/CPU limits, and a random in-memory server password. Only `HOME=/tmp` and the server password are explicitly passed into the container; no Docker socket is mounted. The image must be supplied by deployment configuration and pinned by digest.

These flags and mount policies are tested with a Docker command double, not a Docker daemon. Docker and OpenCode are unavailable here, so actual sandboxing remains BLOCKED. A digest only pins the image; it does not establish that the image is trustworthy. The current no-network policy prevents remote model access; local model/provider configuration must be provisioned inside a trusted image or a future credential/network broker must be implemented. Supervised/autonomous execution remains disabled until server-side approvals exist. The coordinator persists result hashes and summary, but not raw diffs or process output. Never claim a sandboxed run until adversarial tests have passed on the target OS and Docker configuration.
