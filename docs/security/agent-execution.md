# Agent execution security

Agent prompts, repository content, tool output, and model output are untrusted. Run adapters only inside an AgentOS-managed isolated runtime with a run-scoped workspace, explicit resource and network policy, no host credentials, and no Docker socket. A separate Git worktree protects developer edits from direct mutation but is not a security boundary. Never silently execute on the host if a sandbox is missing.

OpenCode permissions are an additional application-level control, not an OS sandbox. `ExecutionCoordinator` currently permits only `read_only`; permission requests are persisted as rejected before sending the rejection response, and secret-like strings are redacted from grant descriptions/resources. `ApprovalAuthorizationService.grantPermission()` creates a permission grant for the authenticated principal after server policy authorizes it. This is a self-grant under policy, not a separate human approval. Principal/run/action/policy/expiry binding is enforced, and grant consumption plus its audit event are atomic in SQLite and PostgreSQL. A policy adapter returns one immutable `(authorized, version)` decision snapshot; a policy deployment after that snapshot is evaluated does not invalidate that in-flight decision. Cancellation observed at an in-transaction checkpoint before commit rolls back consumption and its event. A cancellation arriving after the last checkpoint may race the database commit; if commit wins, the grant and audit remain persisted and the grant stays consumed. The service accepts no client principal argument and fails closed if trusted identity or policy is absent. No concrete authenticated identity source exists; therefore the service is infrastructure only and is not wired to enable supervised execution. The Docker runtime mounts one detached worktree read-only, uses `--network=none`, loopback-only port publishing, non-root UID, `--read-only`, dropped capabilities, no-new-privileges, pid/memory/CPU limits, and a random in-memory server password. Only `HOME=/tmp` and the server password are explicitly passed into the container; no Docker socket is mounted. The image must be supplied by deployment configuration and pinned by digest.

These flags and mount policies are tested with a Docker command double, not a Docker daemon. Docker and OpenCode are unavailable here, so actual sandboxing remains BLOCKED. A digest only pins the image; it does not establish that the image is trustworthy. The current no-network policy prevents remote model access; local model/provider configuration must be provisioned inside a trusted image or a future credential/network broker must be implemented. Supervised/autonomous execution remains disabled until trusted server identity is connected to the policy service and approvals are enforced immediately before execution. Durable result artifacts are captured as described below; OpenCode process output and tests remain unavailable. Never claim a sandboxed run until adversarial tests have passed on the target OS and Docker configuration.

## Result artifact handling

Result binaries are stored outside database event payloads under an AgentOS-owned local object root (default `~/.agentos/artifacts`). Metadata is scoped by the composite run/project relationship and artifact ID; callers must provide all three IDs to read. Locators are opaque relative UUID keys and do not reveal host paths. Staged files use restrictive permissions, are flushed and digest-checked before atomic no-overwrite promotion, and are verified again when read. The service refuses traversal locators and symlinked object directories, limits captures to 5 MiB per artifact and 25 MiB per run by default, records truncation, and supports retention cleanup. Keep the configured root writable only by the AgentOS service account and protect it with the host's backup/access-control policy.

Text outputs pass through the existing secret redactor. Structured artifacts reject secret-bearing field names; execution manifests contain environment variable names only. The OpenCode adapter currently does not expose process stdout/stderr or structured test results, so those rows are marked unavailable. AgentOS does not collect model chain-of-thought. Filesystem storage is the only implemented backend; no cloud credentials are accepted. Filesystem tests cover promotion failure, truncation, invalid locators and database-backed retrieval/integrity; Windows prevents the symlink-specific adversarial tests from running here. Real Docker and OpenCode remain unverified.
