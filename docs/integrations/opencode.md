# OpenCode adapter

AgentOS integrates with OpenCode through the official `@opencode-ai/sdk` and its documented server API. The adapter checks the CLI version using an injected process probe and checks `/global/health` for a configured server. Supported versions are OpenCode `>=1.1.1 <2.0.0`; test each SDK upgrade against the supported server before widening this range.

OpenCode owns its model-provider setup. Selecting a provider registered in AgentOS does not configure OpenCode. The adapter may select a model by OpenCode's `providerID` and `modelID` only after that provider is configured in OpenCode. Do not put credentials in adapter configuration; OpenCode's own credential store remains separate.

Execution requires an injected `IsolatedRuntime`. `DockerIsolatedRuntime` requires an operator-supplied digest-pinned image containing `opencode`, provisions a detached Git worktree, allows only `read_only`, mounts only that worktree read-only, creates a dedicated per-run bridge with outbound masquerading and inter-container communication disabled, exposes the authenticated server on host loopback, applies fixed process/memory/CPU limits and a bounded `/tmp`, and implements stop/kill and generation-scoped cleanup. No Docker socket or privileged mode is used; all Linux capabilities are dropped and no-new-privileges is set. The Docker CLI child receives a filtered environment. The bridge can still reach host-gateway services; enforce host firewall restrictions. An example construction is `new DockerIsolatedRuntime({ image: process.env.AGENTOS_OPENCODE_IMAGE! })`, where the value must end with `@sha256:<64 hex characters>`.

`pnpm --filter @agentos/agents test:docker` builds a disposable Node protocol shim and runs Docker daemon integration checks. It requires Docker Engine and fails if the daemon is unavailable. GitHub Actions has a separate Ubuntu Docker job. These checks exercise actual container settings and lifecycle but do not verify OpenCode compatibility. Docker and OpenCode are unavailable on the current local machine, so no local daemon check or real OpenCode task has run. The network policy blocks ordinary external routing but does not block host-gateway services. Supervised/autonomous modes fail closed until AgentOS approval enforcement exists. OpenCode permission prompts are not host-level authorization. A Git worktree by itself is not a security sandbox, and Docker does not protect against a malicious host kernel or daemon.

The daemon fixture is based on `node:22-alpine@sha256:c610fcdfb1d5b4740dd70c284ed3cb16bb857e0f7166196e36a5501df7a3aa32`; the built test image is then passed to `DockerIsolatedRuntime` by its immutable local image ID. CI prints the daemon server version with `docker version`.

The SDK event stream is normalized for session, execution, tool, structured filesystem and permission events. The coordinator waits for subscription readiness before sending a prompt, persists events in run sequence order, deduplicates repeated SDK source IDs, and discards reasoning/text deltas. Read-only permission requests are recorded as rejected before the SDK response. Result diff collection belongs to the AgentOS workspace manager, not OpenCode response text; only the summary and file/diff hashes are persisted today. Cancellation uses the documented session abort operation. Smoke tests require an OpenCode installation and credentials and are intentionally opt-in; ordinary CI uses controlled doubles. Durable process-restart recovery has not been implemented.

References: [OpenCode SDK](https://opencode.ai/docs/sdk/), [OpenCode server](https://opencode.ai/docs/server/), [OpenCode permissions](https://opencode.ai/docs/permissions/).
