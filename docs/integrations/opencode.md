# OpenCode adapter

AgentOS integrates with OpenCode through the official `@opencode-ai/sdk` and its documented server API. The adapter checks the CLI version using an injected process probe and checks `/global/health` for a configured server. Supported versions are OpenCode `>=1.1.1 <2.0.0`; test each SDK upgrade against the supported server before widening this range.

OpenCode owns its model-provider setup. Selecting a provider registered in AgentOS does not configure OpenCode. The adapter may select a model by OpenCode's `providerID` and `modelID` only after that provider is configured in OpenCode. Do not put credentials in adapter configuration; OpenCode's own credential store remains separate. AgentOS has not implemented a safe provider configuration/credential delivery path for this container.

Execution requires an injected `IsolatedRuntime`. `DockerIsolatedRuntime` requires an operator-supplied digest-pinned image containing `opencode`, provisions a detached Git worktree, allows only `read_only`, mounts only that worktree read-only, creates a dedicated per-run bridge with outbound masquerading and inter-container communication disabled, exposes the authenticated server on host loopback, applies fixed process/memory/CPU limits and a bounded `/tmp`, and implements stop/kill and generation-scoped cleanup. No Docker socket or privileged mode is used; all Linux capabilities are dropped and no-new-privileges is set. The Docker CLI child receives a filtered environment. The bridge can still reach host-gateway services; enforce host firewall restrictions. An example construction is `new DockerIsolatedRuntime({ image: process.env.AGENTOS_OPENCODE_IMAGE! })`, where the value must end with `@sha256:<64 hex characters>`.

The SDK lockfile resolves to `@opencode-ai/sdk@1.19.5`. A matching official image candidate is `ghcr.io/anomalyco/opencode:1.19.5@sha256:f4cfe16d91efbbfca01a51c44094fba4cf82e15c7fa17de5f11f9059699b1e6e` (upstream [package version](https://github.com/anomalyco/opencode/pkgs/container/opencode/versions?filters%5Bversion_type%5D=tagged), [release](https://github.com/anomalyco/opencode/releases/tag/v1.19.5)). The digest is the upstream package version digest; verify platform resolution and image contents with `docker pull` and `docker image inspect` before deployment. It is a candidate, not an AgentOS-verified runtime image. Supply-chain trust remains with the upstream publisher and registry.

`pnpm --filter @agentos/agents test:docker` builds a disposable Node protocol shim and runs Docker daemon integration checks. It requires Docker Engine and fails if the daemon is unavailable. GitHub Actions run [42378655753](https://github.com/rehanbaqir31-gif/agentos/actions/runs/42378655753) passed on Docker Engine 29.4.2 / API 1.54 (Ubuntu 26.04.1 x64). Checks cover actual container settings and lifecycle but do not verify OpenCode compatibility. Docker and OpenCode are unavailable on the current local machine, so no local daemon check or real OpenCode task has run. The network policy blocks ordinary external routing but does not block host-gateway services. Supervised/autonomous modes fail closed until AgentOS approval enforcement exists. OpenCode permission prompts are not host-level authorization. A Git worktree by itself is not a security sandbox, and Docker does not protect against a malicious host kernel or daemon.

The daemon fixture is based on `node:22-alpine@sha256:c610fcdfb1d5b4740dd70c284ed3cb16bb857e0f7166196e36a5501df7a3aa32`; the built test image is then passed to `DockerIsolatedRuntime` by its immutable local image ID. CI prints the daemon server version with `docker version`.

The SDK event stream is normalized for session, execution, tool, structured filesystem and permission events. The coordinator waits for subscription readiness before sending a prompt, persists events in run sequence order, deduplicates repeated SDK source IDs, and discards reasoning/text deltas. Read-only permission requests are recorded as rejected before the SDK response. For SDK 1.19.5, the synchronous prompt response is accepted as success only when `info` is an assistant message for the expected session, has a finite `time.completed` value, and has no `error`. The installed SDK types document `AssistantMessage.time.completed`, its optional error union and the prompt response shape. `MessageAbortedError` and caller aborts classify as cancelled; local deadline aborts classify as timed out; other API/assistant failures classify as failed; absent or mismatched completion metadata classify as incomplete. Empty completed text remains success with a null summary. The coordinator persists timeout/incomplete as failed run states with distinct failure event codes and result metadata. It does not infer success from a generic idle/status event. See the [official OpenCode API](https://opencode.ai/docs/api) and [SDK docs](https://opencode.ai/docs/sdk/).

The adapter captures only non-synthetic, non-ignored assistant `text` parts after secret redaction. It does not persist reasoning parts. The adapter does not expose OpenCode process stdout/stderr or structured test results, which remain explicitly unavailable artifacts. Result diffs come from the AgentOS workspace manager. Cancellation uses the documented session abort operation. Durable process-restart recovery has not been implemented.

## Image provenance and inspection

The operator-selected candidate is `ghcr.io/anomalyco/opencode:1.19.5@sha256:f4cfe16d91efbbfca01a51c44094fba4cf82e15c7fa17de5f11f9059699b1e6e`. Upstream [GHCR package metadata](https://github.com/anomalyco/opencode/pkgs/container/opencode/versions) identifies the 1.19.5 tag and digest. A direct OCI Registry API inspection of the digest returned a Linux multi-architecture OCI index: `linux/amd64` child `sha256:c19f5dd52946ae1bf7cc101acd7ffeea9f5f932091598a1d5bfa1a5a8043763f` and `linux/arm64` child `sha256:26a73fa7002bec51b8f6019677713ddc0b15de02f0c080246ccb2616e54005a2`. The amd64 image config digest is `sha256:82db9c496196a37f9b23f67a0cc2132c80025bc0e9cc5b9245b9584ccf6cb621`; OCI metadata reports Linux/amd64, entrypoint `opencode`, no configured user (Docker defaults to root), working directory `/`, and only `PATH` plus `BUN_RUNTIME_TRANSPILER_CACHE_PATH` environment keys. The runtime must override the entrypoint to avoid invoking `opencode opencode ...`; its CLI probe and server command now explicitly use `--entrypoint=opencode`.

The official [v1.19.5 release](https://github.com/anomalyco/opencode/releases/tag/v1.19.5) is immutable and identifies source commit `810c0eba1a7348036f8bdf61e6632d0c36c6876c`. GitHub's commit verification API reports that commit as **unsigned**. The publisher namespace and registry digest establish where these bytes were published and that the reference is immutable; they do not prove a trusted build chain or runtime compatibility. No Docker pull, filesystem inspection, `opencode --version`, non-root execution or live task has been performed. Treat image content, dependencies, maintainer account and registry as supply-chain risks.

For a future Docker-capable verification host, first inspect the exact image without secrets:

```powershell
$image = 'ghcr.io/anomalyco/opencode:1.19.5@sha256:f4cfe16d91efbbfca01a51c44094fba4cf82e15c7fa17de5f11f9059699b1e6e'
docker pull --platform linux/amd64 $image
docker image inspect --format '{{.Os}}/{{.Architecture}} {{json .Config.Entrypoint}} {{json .Config.User}}' $image
docker run --rm --network=none --read-only --user=10001:10001 --cap-drop=ALL --security-opt=no-new-privileges:true --tmpfs=/tmp:rw,nosuid,nodev,noexec,size=256m --env=HOME=/tmp --entrypoint=opencode $image --version
```

Record the pulled image ID, resolved child digest, CLI version and command exit status. Compare those with the candidate above and SDK support range before proceeding. This is only image inspection; it is not the AgentOS smoke test.

## Smoke-test procedure (not yet executable end to end)

The following procedure is gated on implementation and security review of the host-side credential broker described in [the architecture](../ARCHITECTURE.md). No provider key may be present in the image, container environment, Docker arguments, repository, artifacts, events or logs. Do not enable general outbound access.

1. Use an isolated Linux Docker Engine host, the inspected digest-pinned image and a broker configured for one approved model/provider. Host firewall rules must let only the per-run container network reach the broker port and block other host-gateway and Internet destinations. Use a test account with a small quota and a revocable key stored only in the host secret manager.
2. Create a disposable Git repository with only a short README; record its commit and tree hash. Do not use production source or credentials.
3. Configure AgentOS with that repository, the pinned image, broker model reference and `read_only`. Start the normal `ExecutionCoordinator` path so the Docker runtime verifies authenticated `/global/health` and the actual OpenCode version, then the SDK creates the session and stream-ready handshake before prompt submission. Use the same event repositories, manifest and artifact service as application execution.
4. Submit: “Inspect the repository and report the README's purpose. Do not modify any files.” Verify assistant/session identity, `time.completed`, no response error, ordered persisted events, final text artifact/result summary, manifest, Git diff and unchanged tree hash.
5. Run a separate cancellation case with a longer harmless prompt. Abort after execution starts; verify cancelled run/event state, container stop/force removal, network cleanup and no prompt replay. A separate provider-error case must record failed state without persisting provider response bodies/credentials.
6. Revoke the broker run capability, verify key rotation/revocation behavior, and confirm Docker labels/resources and disposable workspace are removed. Preserve sanitized test evidence only.

This is a documented procedure, not an implemented runnable test command. Current blockers are the missing broker, unavailable Docker CLI/daemon and no provider config. Existing Docker CI uses a disposable protocol shim and must not be counted as real-image or live-task evidence.

**M4.6 live verification is blocked.** This Windows checkout has neither Docker CLI/daemon nor a configured provider. The current Docker runtime injects only `HOME` and its generated server password, mounts no OpenCode provider configuration, and disables ordinary outbound routing. A real model task therefore cannot be honestly run with the current provisioned state. Do not make the image hold credentials or relax network isolation to clear this blocker. No real OpenCode startup, prompt, cancellation/failure, or real-image cleanup result is claimed. The Node protocol shim CI run verifies Docker settings and lifecycle only. To unblock, provide a reviewed credential-broker or local-provider path that fits the isolation policy, plus a Docker daemon; then run a dedicated live smoke test against the pinned candidate image.
