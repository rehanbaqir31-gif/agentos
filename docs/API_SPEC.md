# API Specification

The implemented local API is a Fastify service exposed by `@agentos/api`. It uses Zod-validated requests, bounded pagination, consistent structured errors, cookie-backed sessions and project/run authorization. It binds to loopback only. This is a local single-user API, not a remote multi-tenant service.

Implemented routes: `GET /health`, `POST /auth/login`, `POST /auth/logout`, `GET /auth/session`, project list/create/read, project task list/create, run list/read/start, run events, approvals list/revoke/permission-grant, and run artifact list/read. All resource routes require a live server-validated session and membership/ownership checks; absent identity denies. Run start is unavailable unless a runtime is explicitly configured, and execution authorization rechecks the principal, policy, run state and lease immediately before adapter execution. The only allowed permission mode is `read_only`; permission grants do not enable writes.

Sessions use an opaque random cookie token whose SHA-256 hash alone is persisted. Cookies are HttpOnly and SameSite=Strict. The current API is loopback-only HTTP, so the cookie Secure flag is not set; HTTPS termination and trusted proxies are not implemented. Authentication is a local password configured once at first startup via bootstrap environment variables; no public account enrollment or external identity provider is implemented. The service rejects non-loopback Host/Origin requests and does not enable CORS. Do not expose this service remotely or place it behind a proxy without a reviewed trusted-proxy and TLS/session design.

SSE replay, OpenAPI generation, agent/provider administration endpoints, workflows, evaluations, remote authentication, membership administration and multi-user account lifecycle remain planned. PostgreSQL can back the service, but local SQLite remains the default.
