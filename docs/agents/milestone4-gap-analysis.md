# Milestone 4 execution gap analysis

M4.4 adds a durable one-row-per-run lease, transactional run-plus-lease creation, monotonically increasing fencing generations, owner-conditional heartbeat/release, coordinator heartbeat, and lease-claim recovery that does not replay prompts. M4.5 uses per-run Docker bridges with outbound masquerading and inter-container communication disabled, generation labels for cleanup, bounded stop/kill and a filtered Docker CLI environment. A daemon-backed suite uses a disposable protocol shim, not OpenCode. GitHub Actions run 42378655753 passed on Engine 29.4.2 / API 1.54 (Ubuntu 26.04.1 x64). Engine testing showed that the published API port is unavailable with `--network=none` or Docker's `--internal` bridge; the selected bridge passed the loopback health check and external fetch probe. Host-gateway access remains a documented risk. Local Docker is unavailable. Deterministic artifact identities and immutable promotion address duplicate capture; metadata-free promoted objects remain grace-period orphans, and retention defers object removal to reduce read races. SQLite and PGlite test the APIs locally. Actual PostgreSQL 16 locking and multiple independent worker processes remain verification gates. Do not begin Phase 5.

Audit basis: `packages/core`, `packages/database`, `packages/providers`, `packages/agents`, lifecycle/security documentation, database migrations, and adapter/repository tests.

Migration version 2 adds approval principal, policy version, expiry, consumption and revocation fields plus a principal/state index. Version 3 adds `run_artifacts` with a composite run/project foreign key and integrity/status constraints. Version 4 adds worker leases. Version 5 adds principals, sessions storing only token hashes, project memberships and run ownership. Both dialects have matching forward migration definitions; live PostgreSQL 16 verification for v5 is pending CI. Event payloads are JSON; artifact events contain only identifiers, digests, sizes and collection statuses. The local API and pre-adapter authorization boundary are implemented, but external auth, account lifecycle and independent human approval are not.

## Delivery boundary

M4.1-M4.6A have prior SQLite, PostgreSQL 16 and Docker-daemon CI evidence. M4.7 local changes are implemented but require their own CI run. The daemon suite uses a protocol shim and does not verify OpenCode. The official image's CLI entrypoint and public OCI metadata are documented but image pull/start/task remains unverified. Real OpenCode startup/task/cancellation/cleanup and the provider broker remain blocked. Process stdout/stderr and structured test results are unavailable. Durable leases exist, but independent-process recovery verification remains open. The authenticated local boundary is not a remote multi-user system. Supervised/write and autonomous modes remain disabled; `read_only` is the only enabled mode. Phase 5 is not started.
