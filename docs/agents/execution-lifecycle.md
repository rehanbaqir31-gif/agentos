# Execution lifecycle

The core run lifecycle is the source of truth: `created → validating → preparing_workspace → queued → running`, with terminal `succeeded`, `failed`, or `cancelled` outcomes and `waiting_for_approval` for external decisions. Persist status transitions and normalized events using `@agentos/core` contracts and database repositories. Session identity is associated with the run; results come from the run workspace's Git state. Cancellation must be safe to repeat. A process restart should reconcile active runs against persisted adapter session state before resuming or marking them failed.

`GitWorkspaceManager` now creates a detached per-run worktree at a full commit SHA, preserves source edits, collects changed paths/hash/diff and removes only its owned worktree. `DockerIsolatedRuntime` requires an image pinned by digest, mounts only that worktree read-only, applies the documented per-run network profile, binds the OpenCode server to host loopback, drops Linux capabilities, applies fixed CPU/memory/process limits, and kills/cleans up on cancellation/disposal. The local API authenticates a principal through a verified database-backed session and establishes server-side request context. The coordinator verifies project membership at admission and rechecks session, policy, run/task status, permission mode and current lease generation immediately before adapter invocation. It deliberately refuses `supervised` and `autonomous`.

`ExecutionCoordinator` creates a run, validates project/task/agent/provider selection, advances lifecycle statuses, allocates and attaches a session, writes a versioned manifest, ingests normalized SDK events after a subscription-ready handshake, and captures artifacts before closing the run workspace. The artifact service stores diff, manifest and structured result metadata as filesystem objects with database metadata; stdout, stderr and test results are captured only when the adapter supplies them, otherwise their metadata explicitly says `unavailable`. Run events keep only artifact references, hashes, sizes and collection statuses. Source event IDs and permission records are deduplicated. Read-only permission requests are durably rejected before the adapter response; broader approvals fail closed. Coordinator and real filesystem tests run against SQLite; adapter process output remains unavailable with the current OpenCode integration.

If artifact persistence fails, the run cannot be marked successful. Failure/cancellation paths attempt to collect a partial result while the session still exists. Artifact capture is bounded (5 MiB per object; 25 MiB per run by default), truncation is explicit, content hashes are verified at write and retrieval, and reads require the exact run/project/artifact scope. Current storage is local filesystem only; no cloud object-store driver is configured.

`ApprovalAuthorizationService.grantPermission()` issues a server-policy-authorized permission grant to the currently authenticated principal. This is not an independent human approval and there is no multi-user approver flow. Consumption validates principal, run, exact action, policy snapshot version, expiry, revocation and unused state, then updates the grant and inserts the ordered audit event in one transaction on SQLite or PostgreSQL. Audit insertion failure rolls back consumption. Cancellation before or during the transaction prevents commit; cancellation detected after commit leaves the grant consumed and its event persisted. Policy authorization returns its version and decision from one immutable snapshot; a policy change after snapshot evaluation does not retroactively invalidate that in-flight decision. The local policy denies write actions, so no grant enables execution. Authorization is checked immediately before adapter invocation; revocation after an action starts cannot undo it. Execution remains read-only.

`recoverInterruptedRuns()` scans persisted nonterminal runs and attempts an atomic lease claim. It skips any run whose lease is still active, and only the winner of an expired/released/legacy lease claim may mark it interrupted. The recovery worker cleans containers and per-run bridge networks carrying AgentOS-managed, exact run-ID and prior-generation labels (legacy runs have no generation label), removes only the validated run worktree under the OS temporary directory, then stores `run.recovered` and `PROCESS_INTERRUPTED` events and marks the run failed. It never replays a prompt or deletes existing artifacts. Run creation and generation-1 lease insertion share a transaction. Lease lifecycle and stale generation checks are implemented for both backends; SQLite and PGlite tests pass locally, and PostgreSQL locking behavior is verified by PostgreSQL 16 CI. Docker cleanup and cancellation against a real daemon passed for the disposable shim in CI run 42378655753; the local Windows host has no Docker CLI. Raw durable diffs and result metadata are implemented. Capturing OpenCode process stdout/stderr and structured test results remains unavailable because the current adapter does not expose them.
