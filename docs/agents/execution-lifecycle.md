# Execution lifecycle

The core run lifecycle is the source of truth: `created → validating → preparing_workspace → queued → running`, with terminal `succeeded`, `failed`, or `cancelled` outcomes and `waiting_for_approval` for external decisions. Persist status transitions and normalized events using `@agentos/core` contracts and database repositories. Session identity is associated with the run; results come from the run workspace's Git state. Cancellation must be safe to repeat. A process restart should reconcile active runs against persisted adapter session state before resuming or marking them failed.

`GitWorkspaceManager` now creates a detached per-run worktree at a full commit SHA, preserves source edits, collects changed paths/hash/diff and removes only its owned worktree. `DockerIsolatedRuntime` requires an image pinned by digest, mounts only that worktree read-only, disables networking, binds the OpenCode server to host loopback, drops Linux capabilities, applies fixed CPU/memory/process limits, and kills/cleans up on cancellation/disposal. It deliberately refuses `supervised` and `autonomous` because AgentOS approvals are not implemented.

The durable coordinator is still absent. Run/session/result state is not persisted together; a process restart cannot discover/reconcile containers, and the current Docker image/server lifecycle does not restore sessions. Do not report this lifecycle as end-to-end complete. Real Docker isolation is also unverified on this machine.
