# Execution lifecycle

The core run lifecycle is the source of truth: `created → validating → preparing_workspace → queued → running`, with terminal `succeeded`, `failed`, or `cancelled` outcomes and `waiting_for_approval` for external decisions. Persist status transitions and normalized events using `@agentos/core` contracts and database repositories. Session identity is associated with the run; results come from the run workspace's Git state. Cancellation must be safe to repeat. A process restart should reconcile active runs against persisted adapter session state before resuming or marking them failed.

`GitWorkspaceManager` now creates a detached per-run worktree at a full commit SHA, preserves source edits, collects changed paths/hash/diff and removes only its owned worktree. `DockerIsolatedRuntime` requires an image pinned by digest, mounts only that worktree read-only, disables networking, binds the OpenCode server to host loopback, drops Linux capabilities, applies fixed CPU/memory/process limits, and kills/cleans up on cancellation/disposal. It deliberately refuses `supervised` and `autonomous`; trusted authentication is not implemented and the approval service is not wired into execution.

`ExecutionCoordinator` now creates a run, validates project/task/agent/provider selection, advances lifecycle statuses, allocates and attaches a session, writes a versioned manifest, ingests normalized SDK events after a subscription-ready handshake, collects a result snapshot, persists its file/diff hashes, and records terminal completion/failure/cancellation. Source event IDs and permission records are deduplicated. Read-only permission requests are durably rejected before the adapter response; broader approvals fail closed. Coordinator tests run against SQLite.

`ApprovalAuthorizationService.grantPermission()` issues a server-policy-authorized permission grant to the currently authenticated principal. This is not an independent human approval and there is no multi-user approver flow. Consumption validates principal, run, exact action, policy snapshot version, expiry, revocation and unused state, then updates the grant and inserts the ordered audit event in one transaction on SQLite or PostgreSQL. Audit insertion failure rolls back consumption. Cancellation before or during the transaction prevents commit; cancellation detected after commit leaves the grant consumed and its event persisted. Policy authorization returns its version and decision from one immutable snapshot; a policy change after snapshot evaluation does not retroactively invalidate that in-flight decision. No trusted authentication implementation exists, so the service is not wired to execution and execution remains read-only.

`recoverInterruptedRuns()` is an explicit single-worker startup operation: it finds persisted nonterminal runs, asks the adapter/runtime to remove containers carrying both AgentOS-managed and exact run-ID labels, removes only the validated run worktree under the OS temporary directory, then marks the run failed with a `PROCESS_INTERRUPTED` event. It never replays a prompt. Call it before accepting new work. Database reopening is tested on SQLite and the runtime cleanup logic uses command-double plus real Git worktree tests. Real Docker cleanup remains unverified; this does not acquire distributed leases or reattach sessions. Persisted raw diffs/artifact bundles, stdout/stderr and test capture are also outstanding.
